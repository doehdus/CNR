# 실험 프로토콜

상위 기준: [프로젝트 확정 사항](../PROJECT_CONTEXT.md)

현재 로컬 환경에는 기준 음성 3개·소음 원본 3개·혼합 입력 36개·초기 고정형 SS 출력 36개가 등록되어 있고, 무처리·초기 SS 72개의 STOI·ESTOI를 계산했다. 파일 존재와 계산 완료는 목표 SNR·클리핑·소음 출처의 검증 완료와 구분한다. 실제 음원·결과는 GitHub에 포함하지 않으며 새 팀원은 별도로 전달받는다. 이 문서는 현재 실험 기준이다. 후속 처리 방식의 구현·산출물 인수는 별도 대기 항목으로 관리한다.

## 1. 선정 음성과 조건

2026-11-12 최종 결정으로 다음 녹음 **3개만** 이번 실험의 기준 음성으로 사용한다.

| 문장 ID | 녹음자 | 문장 |
| --- | --- | --- |
| `instruction_01` | 유채원 | 기사님, 장비를 뒤로 2미터 이동해 주세요. |
| `instruction_02` | 유채원 | 각재 3개를 오른쪽 적재장으로 옮겨 주세요. |
| `warning_01` | 김도연 | 정지! 장비 뒤에 사람 있습니다! |

녹음자는 문장에 고정된다. 두 사람의 녹음 전체 6개를 사용하는 가정은 현재 설계에서 제외한다. 선정 원음 3개와 혼합 입력 36개는 현재 로컬에 등록돼 있다. 파일 존재·재생·객관 지표 계산과 목표 SNR·클리핑·소음 출처 검증은 구분한다.

| 변수 | 기준 |
| --- | --- |
| 소음 | 단일·복합·변화 |
| 입력 SNR | 20, 10, 5, 0 dB |
| 문장 | 선정된 작업 지시 2개·위험 경고 1개 |
| 처리 방식 | 무처리, 초기 고정형 SS, 후속 사전패턴 고정형·갱신형 SS, 추가 알고리즘(미선정) |

### 소음 정의

| 조건 | 기존 설계 정의 | 목적 |
| --- | --- | --- |
| 단일 | 한 종류의 장비 소음이 지속되는 동안 문장 발화 | 일정한 소음에서의 성능 |
| 복합 | 두 종류의 장비 소음이 처음부터 동시에 지속되는 동안 문장 발화 | 혼합 스펙트럼 처리 |
| 변화 | 초기 소음 추정 후 새로운 소음이 추가되고 비발화 구간을 거친 뒤 문장 발화 | 고정형·갱신형의 변화 대응 |

유채원은 소음 3종·SNR 4단계 합성 데이터를 보유한다. 실제 소음 파일·출처·혼합 비율·변화 시점·비발화 구간 길이를 검증 자료에 기록하고 위 설계와의 일치 여부를 확인한다.

## 2. 인수와 합성 조건 검증

1. 선정 기준 음성 3개와 합성에 사용한 소음의 파일·출처를 기록한다.
2. 실제 WAV 형식, SNR 계산 구간, 정규화·클리핑 규칙을 확인한다.
3. 초기 소음 추정용 소음만 있는 구간의 위치·길이를 확인한다.
4. 3문장 × 소음 3종 × SNR 4단계의 36개 조건과 실제 인수 파일 목록을 대조한다.
5. 혼합·처리 음원이 해당 녹음자·문장의 기준 음성과 시간 정렬되는지 확인한다.
6. 경로·조건·검증 정보를 `data/metadata/`에 기록한다.

기존 발화 구간 기준 SNR은 권장안이며 최종 계산 규칙은 아직 인수·확인하지 않았다. 특히 변화 소음의 전체 파일·발화 구간·변화 이후 발화 구간 중 어느 범위를 사용했는지 확인한다. 목표 SNR과 실제 측정값을 구분한다.

PCM WAV / 16 kHz / 16-bit / mono는 기존 권장안이다. 기준 원음은 총 3개이며 각 혼합·처리 음원의 초기 비발화 구간을 포함한 시간 대응을 관리한다.

## 3. 알고리즘

### 초기 추정값 고정형 SS

소스 위치: `algorithms/ss_fixed/main.c`. 초기 고정형 SS 출력 36개는 `outputs/ss_fixed/`에 등록돼 있다. 처리 파라미터·버전과 동일 입력의 재현 여부는 별도로 기록한다.

입력 처음의 소음만 있는 구간에서 평균 소음 크기 스펙트럼을 추정한다. 이를 전체 파일에서 고정해 각 프레임의 크기 스펙트럼에서 차감한다. 원래 위상을 사용해 IFFT와 중첩 합산(OLA)으로 복원하여 WAV로 저장한다. 소음 변화 조건에서도 자동 갱신하지 않는다.

### 후속 방식

다음 세 C 파일은 현재 빈 구현 자리다. 아래 설명은 후속 구현의 설계 기준이며 완료된 처리 결과를 뜻하지 않는다.

- 사전패턴 고정형: `algorithms/ss_pattern_fixed/main.c`. 초기 입력과 유사한 사전 소음 패턴을 선택·크기 보정한 뒤 고정한다. 패턴 구축·선택·보정 방법은 세부 확정이 필요하다.
- 사전패턴 갱신형: `algorithms/ss_pattern_update/main.c`. 같은 초기값에서 시작하여 비발화 구간에 추정값을 갱신한다. 발화 중에는 최근 값을 사용한다. 비발화 판정·주기·갱신량은 미확정이다.
- 추가 알고리즘: `algorithms/additional/main.c`. 명칭·처리 방식은 미선정이다.

SS 공통 흐름은 프레임 분할 → 윈도잉 → FFT → 추정·차감 → IFFT → OLA → WAV 저장이다. 공통 파라미터를 동일하게 유지한다. 기존 256샘플 프레임은 참고안이며 길이·중첩률·윈도·차감 강도·최소 스펙트럼 값·초기 추정 구간의 실제 구현값과 버전을 기록한다.

## 4. 산출물과 경로

| 항목 | 위치 | 목표 |
| --- | --- | --- |
| 선정 원음 | `data/clean/` | 3개 |
| 소음 원본·구성 | `data/noise/` | 출처·구성 기록 |
| 혼합 입력 | `data/mixed/` | 36개 |
| 경로·조건·검증 정보 | `data/metadata/` | 입력·출력과 대응 |
| 초기 고정형 SS | `outputs/ss_fixed/` | 36개, 현재 등록 완료 |
| 사전패턴 고정형 SS | `outputs/ss_pattern_fixed/` | 36개 |
| 사전패턴 갱신형 SS | `outputs/ss_pattern_update/` | 36개 |
| 추가 알고리즘 | `outputs/additional/` | 선정·구현 후 36개 |

누적 처리 출력은 초기 고정형 36개, SS 3종 108개, 추가 1종 포함 144개다. 무처리 36개 포함 평가 후보는 각각 72·144·180개다. 실제 등록·검증 수와 목표 개수는 구분한다.

홈페이지의 [dataset.json](../data/metadata/dataset.json)은 기준 음성 3개와 무처리 36개·네 처리 방식 144개의 연결 경로, 소음 원본 3개를 정의한다. 실제 파일 보유 목록이 아니다. 기본 파일 이름·경로 변경은 [홈페이지 사용 안내](../site/README.md)를 따른다.

음원 식별자에 녹음자·문장·소음·SNR·처리 방식이 정확히 대응해야 한다. 소음 출처·측정 SNR·계산 구간·형식·정렬·파라미터·버전은 실제 인수 자료에 별도 기록한다. WAV 파일 존재·형식·길이·정렬·SNR·클리핑과 동일 입력 사용을 확인한 뒤 [평가 프로토콜](evaluation-protocol.md)로 넘긴다.

## 5. 계산 코드와 결과 데이터 전달

STOI·ESTOI 계산은 `metrics/`의 독립 Python 도구로 수행한다. `calculate-metrics.cmd`의 기본 대상은 무처리·초기 SS 72개이며, 완료 JSON·CSV는 `results/metrics/`에 기록한다. 후속 음원이 준비되면 CLI의 `--algorithm` 또는 계산 함수의 `sample_ids`로 대상을 정한다.

홈페이지는 완료 JSON만 전달받는다. `build-site.cmd`가 ID·중복·두 점수·계산 출처를 검증해 사이트 사본에 반영하고 빌드한다. 웹 빌드는 Python 계산을 실행하지 않는다. 결과와 현재 WAV의 경로·SHA-256이 다르면 홈페이지에서 지표 표시를 보류한다.

자동 지표 전달에 DB는 필요하지 않다. QR 회차·참가자·청음 응답 등 공유 입력은 D1에 저장한다. 세부 계약은 [결과 데이터 안내](../results/README.md), 현재 평가 수집은 [평가 프로토콜](evaluation-protocol.md)을 따른다.
