# 연구 흐름 검토

> 2026-11-15 검토: 이 문서의 아래 본문은 이전 설계·검토 기록이다. 현재 실행 지침은 [협업 안내](../CONTRIBUTING.md), 화면·데이터 구조는 [사이트 구조](../site/ARCHITECTURE.md), 평가는 [평가 프로토콜](evaluation-protocol.md)을 따른다. 과거 폴더·시작 파일·브라우저 저장·종이 전용 수집·미완료 표시는 당시 기록으로 보존한다.

## 현재 기준 요약

현재 운영 소스는 `site/frontend/`·`site/backend/`·`site/shared/`로 분리돼 있고 일곱 메뉴·QR/D1 수집을 사용한다. 계산은 독립 `metrics/`, 완료 JSON·CSV는 `results/metrics/`다. `calculate-metrics.cmd`로 계산하고 `build-site.cmd`로 결과 검증·반영·웹 빌드를 실행한다. 웹 빌드는 계산기를 호출하지 않으며 운영 배포는 별도다. 자동 지표 전달에는 DB가 필요하지 않고 D1은 공유 청음 응답·설정 등에 사용한다.

로컬 검증 기준은 WAV 78개와 무처리·초기 SS 지표 72개다. 실제 청음 응답 건수는 운영 DB에서 확인한다. 과거 로컬 홈페이지·시작 파일과 미사용 UI·D1 예제는 현재 저장소에 포함하지 않는다.

## 아래는 과거 기록


2026-11-12 사용자 제안: 음원 저장 → 알고리즘 출력 시연 → STOI·ESTOI와 종이 청취 평가 → 조건별 효과 비교 → 알고리즘별 반복 → 최종 결과물.

이 흐름은 연구 목적에 적합하다. 아래 항목은 연구 설계를 보완하기 위한 검토이며 DB·보고서 기능이 모두 구현되었다는 의미는 아니다.

## 1. 두 가지 연구 질문을 구분한다

| 질문 | 비교 방법 |
| --- | --- |
| 어느 소음·SNR에서 알고리즘이 효과적인가? | 같은 혼합 입력에 대한 무처리 대비 처리 결과의 개선량 |
| STOI·ESTOI가 사람의 이해도를 잘 반영하는가? | 같은 음원의 객관 지표와 사람 이해도 평균 사이의 관계 |

STOI·ESTOI는 깨끗한 기준 음성과 무처리 또는 처리 음성을 각각 비교해 계산한다. 두 계산값의 차이가 개선량이다. [참조 구현](https://github.com/mpariente/pystoi)

- ΔSTOI = 처리 STOI − 같은 조건의 무처리 STOI
- ΔESTOI = 처리 ESTOI − 같은 조건의 무처리 ESTOI
- 사람 이해도 개선량 = 처리 이해도 − 같은 조건의 무처리 이해도

0~10 청취 점수와 STOI·ESTOI를 서로 빼거나 임의로 합산하지 않는다. 자연스러움·소음 방해·핵심 정보 정답률도 구분한다. 소음 감소와 음성 손상을 함께 확인하고 개선·유지·악화 결과를 모두 보고한다.

## 2. 같은 입력으로 알고리즘을 반복한다

선정 원음은 유채원 지시 2개·김도연 경고 1개다. 혼합 입력은 36개로 고정하고 모든 알고리즘이 같은 파일을 처리한다. 파일 지문·알고리즘 버전·파라미터를 기록해 재현성을 확보한다.

초기 고정형 단계의 평가 후보는 무처리 36 + 처리 36 = 72개다. SS 3종을 비교하면 무처리 36개를 공유하여 총 144개 후보가 된다. 평가자는 무처리·알고리즘 조건 간 동일하거나 균형 잡힌 배정을 사용한다. 반복 자료를 서로 독립된 표본처럼 단순 합산하지 않는다.

## 3. 시연과 정식 청취 평가를 구분한다

홈페이지는 연구자가 조작하는 시연 화면으로 적합하다. 정식 평가자에게는 원문·깨끗한 기준 음성·알고리즘명·객관 점수·다른 사람 점수를 미리 공개하지 않는 구성이 필요하다. 이미 정답 내용을 아는 사람의 응답은 처음 듣고 이해한 결과와 구분해야 한다.

재생 순서·음원 배정은 무작위·균형 배정을 사용하고 재생 장치·볼륨·횟수·휴식과 익명 평가자 ID를 기록한다. 공식 청취시험 사례에서도 순서 효과를 줄이기 위해 무작위·균형 배정을 사용한다. [NTIA 청취시험 사례](https://www.govinfo.gov/content/pkg/GOVPUB-C60-PURL-LPS107135/pdf/GOVPUB-C60-PURL-LPS107135.pdf)

문장이 3개뿐이라 반복 중 내용 기억 효과가 남을 수 있다. 특히 소음×SNR마다 객관 지표가 문장 3개에서 나오므로 조건별 상관계수만으로 최적 조건을 단정하지 않는다. 연구 결론은 현재 문장·녹음자·소음·평가자 범위의 탐색 결과로 제한하고 문장별 변화도 함께 제시한다.

## 4. 저장·입력 구조

로컬 연구에는 WAV를 파일로 보관하고 SQLite 등에 경로·메타데이터·관계를 저장하는 구성을 권장한다. 모든 WAV를 DB의 BLOB으로 저장할 필요는 없다.

연결할 정보는 다음과 같다.

- 음원: ID, 원음·소음·혼합·처리 구분, 기준·입력 음원 ID, 문장·녹음자·소음·SNR, 경로·지문
- 알고리즘: 이름·버전·공통 및 개별 파라미터
- 객관 평가: 음원 ID, STOI·ESTOI, 계산 버전·평가 구간·입력 지문
- 청취 평가: 세션·익명 평가자·음원 ID, 실제 재생 순서, 종이 원응답·3척도·핵심 정보 채점 기준
- 결과: 원자료를 유지하면서 재생성할 수 있는 집계·분석과 확정 버전

종이로 응답을 받은 뒤 음원 ID·평가자 ID로 입력하고 즉시 평균·응답 수를 갱신하는 흐름은 적합하다. 입력 중 결과는 ‘집계 중’으로 표시하며 누락·중복·수정과 채점 기준을 확인한 뒤 최종 결과를 확정한다.

## 5. 최종 결과물

- 개별 음원의 객관 지표 CSV·JSON, 개별 평가자 원응답 CSV·JSON
- 알고리즘×소음×SNR별 처리 전후 평균·개선량, 유효 음원·평가자·응답 수와 편차
- 문장별 결과, 조건별 개선량 그래프·표, 객관 지표↔사람 이해도 산점도·Spearman
- 알고리즘별 효과가 관찰된 조건·악화된 조건과 연구 한계를 담은 비교 요약

불확실성·통계 검정은 실제 평가자 배정과 반복 측정 구조를 정한 뒤 설계한다. 같은 평가자의 전후 응답을 직접 비교하려면 동일 조건의 대응이 보존되어야 한다. 시연 중의 소수 응답만으로 지표나 알고리즘의 우열을 확정하지 않는다.

## 6. 검토 당시 구현과 추가 범위

검토 당시 구현: 내부 Python 계산 함수, 파일·JSON 음원 설정, 3단계 홈페이지와 36조건 표, 종이 응답의 브라우저 입력·집계·백업, 객관 지표와 이해도 평균의 상관분석.

검토 당시 추가 범위: DB 영구 저장·평가 세션과 배정 관리, 평가자용 정보 숨김, 조건별 사람 평가 개선량·편차·알고리즘 비교 집계, 결과 확정과 연구 보고서용 그래프·요약 내보내기. 현재 기본 분석 JSON·원응답 CSV 내보내기는 이러한 최종 연구 결과물 전체와 구분한다.
