# ConstructionNoiseReduction

공사 소음 환경의 깨끗한 음성·소음·합성음을 분석해 Butterworth 전처리와 고정형 SS·Wiener·Log-MMSE의 파라미터 후보를 정합니다. WAV 오프라인 처리 결과의 STOI·ESTOI와 청취평가를 비교해 작업 지시·위험 경고의 전달 효과를 분석한 보고서를 작성합니다.

## macOS에서 로컬 실행

Node.js 22.23.4가 준비된 환경에서 실행합니다. Node.js 설치는 필요한 팀원이 직접 진행합니다.

```bash
cd website
npm ci
npm run dev
```

`npm ci`는 처음 실행하거나 의존성 잠금 파일이 변경됐을 때 사용합니다. 이후에는 `git pull` 후 `npm run dev`로 실행합니다.

개발 서버가 현재 입력 음원과 로컬 DB를 준비합니다. 브라우저에서 `http://localhost:5173/website/`에 접속합니다. 배포 계정 설정은 필요하지 않습니다. 새 분석·처리 결과는 완료 후 연결합니다.

## 진행 방향

1. **자료 준비** — 등록된 깨끗한 음성·소음·합성음과 대응 기준음을 확인합니다.
2. **세 자료 재분석** — Clean·Noise·Mixture를 보고서의 질문에 맞춰 분석합니다. 기존 Noise·Mixture 분석도 체계화해 새 회차로 다시 수행하고 후보 선정 근거를 모읍니다. C로 수치를 저장하고 Python은 완료 수치의 그래프를, 웹은 결과 조회를 담당합니다.
3. **후보 선정과 처리** — 분석을 근거로 Butterworth와 고정형 SS·Wiener·Log-MMSE의 후보를 정합니다. Butterworth는 세 알고리즘 앞의 전처리로 적용합니다.
4. **객관 평가와 청취평가** — 최종 처리 음원의 STOI·ESTOI를 계산한 뒤 정해진 기준으로 청취평가 음원을 선정합니다.
5. **비교 보고서** — 같은 문장·화자·소음·SNR의 객관 지표와 청취평가 결과를 대응시켜 분석 보고서를 작성합니다.

합성 계획 12개 원음 × 소음 3종 × SNR 4단계의 144개를 실제 등록했습니다. 전체 합성 조건에 공통 후보의 모든 조합을 적용합니다. 확정한 처리 조합과 생성 계획 수량은 아래 최종 목적 기록을 따르며 청취평가 참여 인원은 추후 정합니다.

확정한 13단계·공통 후보 수·전체 처리 계획과 재분석 설계는 [최종 목적과 실험 진행 순서](PROJECT_CONTEXT.md#2026-11-23-최종-목적과-실험-진행-순서)를 따릅니다. 세부 파라미터·분석 조건·청취평가 선정 기준은 해당 단계에서 필요한 항목부터 하나씩 정합니다.

GitHub에는 현재 입력 WAV 171개와 코드·설정·검사 자료를 공유합니다. 이전 분석·처리·평가는 로컬 `before1123/`에 보관합니다. [폴더 구조와 실행 방법](CONTRIBUTING.md)을 따릅니다.

## 현재 진행

이번 선정의 분석 기록·기본 그래프 24장·후보 비교 그래프 3장은 유지합니다. 입력 원음·소음·기준음·합성음 171개도 그대로 보존했습니다.

확정한 두 Butterworth 필터의 SOS 계수를 각각 C 코드에 넣고, 공통 출력 감쇠 −1.7dB로 중간 WAV를 **각 144개, 총 288개** 생성·검증했습니다. 독립 SciPy 처리와 최대 차이는 **0 LSB**, 클리핑은 0샘플입니다. 회차별 결과는 WAV 144개·통합 기록 1개·코드 사본 2개의 **147파일**로 보존합니다.
